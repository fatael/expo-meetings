# מערכת שיבוץ פגישות לתערוכות

כלי למארגן תערוכה: מעלים שני קובצי Excel (משתתפים ובקשות פגישה של המבקרים), והמערכת מפיקה לוח פגישות מאוזן בין הביקוש להיצע, ללא התנגשויות.

*An organiser's tool for trade shows: upload two Excel files (participants and visitors' meeting requests) and get a balanced, conflict-free meeting timetable. The interface is available in Hebrew and English.*

## מה המערכת עושה

1. **הקמת תערוכה** – שם, אורך פגישה (10, 15 או 20 דקות), מצב ישיבה, תקרת פגישות למבקר, וטווחי שעות. הפסקה היא הרווח בין שני טווחים (למשל 11:00–13:00 ואחריו 13:30–15:00).
2. **קובץ משתתפים** – מציגים ומבקרים. עמודות: `מזהה`, `סוג` (מציג / מבקר), `שם`, ולפי הצורך `חברה`, `דוא"ל`, `טלפון`, `שולחן`.
3. **קובץ בקשות** – שני מבנים מתקבלים: שורה לכל בקשה (עמודות `מזהה מבקר`, `מזהה מציג`), או שורה לכל מבקר ואחריה המציגים שביקש, לפי סדר העדיפות. סדר ההופעה של הבקשות של כל מבקר הוא סדר העדיפות שלו. במבנה הראשון אפשר להוסיף עמודת `עדיפות` מפורשת. בקשה שמופיעה פעמיים נספרת פעם אחת.
4. **בדיקת תקינות** – קובץ עם שגיאה אינו נטען כלל, ומוצגת רשימת השורות הבעייתיות. הקריאה סלחנית למבנה: שורות כותרת מעל שורת העמודות, עמודות נוספות, שמות עמודות נפוצים (למשל "שם מלא", "קוד משתתף"), והבדלי אותיות גדולות וקטנות במזהים.
5. **הרצת שיבוץ** – ראו "איך פועל השיבוץ" למטה.
6. **תיקון ידני** – הוספה, הזזה ומחיקה של פגישות, עם בדיקת התנגשויות, ונעילת הלוח.
7. **הפצה** – קובץ Excel (כל הפגישות, בקשות שלא נענו, עומס לכל משתתף) וקובצי PDF עם לוח אישי בעמוד נפרד לכל משתתף.

אפשר להוריד תבנית לכל אחד משני הקבצים ממסך התערוכה. כותרות העמודות מתקבלות בעברית או באנגלית.

## איך פועל השיבוץ

השיבוץ נעשה בשני שלבים (הקוד ב-`meetings/scheduler.py`):

- **אילו בקשות נענות.** כל משתתף יכול לקיים פגישה אחת בכל חלון זמן, ולכן מציג אינו יכול לקבל יותר פגישות ממספר חלונות הזמן. כשהביקוש גדול מההיצע, המערכת מחלקת את הפגישות באופן הוגן: הפגישה הראשונה של מבקר שווה יותר מהפגישה השנייה של כל מבקר אחר, השנייה יותר מהשלישית, וכן הלאה. בתוך כך מועדפות הבקשות שהמבקר דירג גבוה יותר. החישוב נעשה בספריית האופטימיזציה OR-Tools.
- **מתי כל פגישה מתקיימת.** לאחר שנבחרו הפגישות, המערכת מוצאת לכל אחת חלון זמן כך שאף משתתף אינו משובץ לשתי פגישות באותה שעה. מובטח מתמטית שפתרון כזה קיים.
- **צמצום המתנות.** לבסוף המערכת מזיזה פגישות, בלי ליצור התנגשויות, כך שלכל משתתף יהיו כמה שפחות חלונות ריקים בין פגישה לפגישה. הצד שעובר בין השולחנות מקבל עדיפות על פני הצד היושב. אותם קבצים מניבים תמיד אותו לוח.

הרצה חוזרת מחליפה את כל הלוח, כולל תיקונים ידניים (המערכת מבקשת אישור לפני כן). לכן מריצים עד שמרוצים מהתוצאה, מתקנים ידנית, ונועלים.

## התקנה בענן בלי ידע טכני (Render)

המאגר כולל קובץ `render.yaml` שמקים את האתר ואת בסיס הנתונים יחד.

1. נכנסים ל-https://dashboard.render.com ומחברים את חשבון ה-GitHub.
2. לוחצים **New** ואז **Blueprint**, ובוחרים את המאגר הזה.
3. ממלאים שם משתמש וסיסמה למנהל המערכת (`ADMIN_USERNAME`, `ADMIN_PASSWORD`) ומאשרים.
4. בסיום ההקמה נכנסים לכתובת שמופיעה בראש עמוד השירות.

משתמש המנהל נוצר אוטומטית בהפעלה הראשונה. משתמשים נוספים מוסיפים במסך `/admin/`.

## התקנה על שרת עצמאי (Docker)

נדרש שרת עם Docker.

```bash
cp .env.example .env
```

ממלאים בקובץ `.env` מפתח סודי, סיסמה לבסיס הנתונים וכתובת האתר, ואז:

```bash
docker compose up -d --build
```

```bash
docker compose exec web python manage.py createsuperuser
```

המערכת זמינה בפורט 8000. מומלץ להציב לפניה שרת עם HTTPS. משתמשים נוספים מוסיפים במסך `/admin/`.

## הרצה מקומית לפיתוח

נדרש Python 3.12 ומעלה. להפקת PDF נדרשות ספריות Pango במערכת ההפעלה (ב-Debian/Ubuntu: `libpango-1.0-0 libpangoft2-1.0-0`).

```bash
python -m venv .venv && . .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

```bash
python manage.py migrate && python manage.py createsuperuser
```

```bash
python manage.py runserver
```

ללא הגדרות נוספות המערכת משתמשת בקובץ SQLite מקומי.

קובצי דוגמה בגודל מלא (300 מציגים, 400 מבקרים):

```bash
python manage.py make_sample_files sample
```

בדיקות אוטומטיות:

```bash
python manage.py test
```

## הגדרות (משתני סביבה)

| משתנה | תפקיד |
| --- | --- |
| `SECRET_KEY` | מפתח סודי של האתר. חובה בסביבת ייצור |
| `DEBUG` | `1` לפיתוח, `0` לייצור |
| `DATABASE_URL` | כתובת בסיס הנתונים, למשל `postgres://user:pass@host:5432/db` |
| `ALLOWED_HOSTS` | שמות המתחם של האתר, מופרדים בפסיק |
| `CSRF_TRUSTED_ORIGINS` | כתובות האתר עם `https://`, מופרדות בפסיק |
| `SCHEDULER_TIME_LIMIT` | תקרת זמן להרצת שיבוץ, בשניות (ברירת מחדל 30) |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | אם הוגדרו, נוצר משתמש מנהל בהפעלה הראשונה |

## מבנה הקוד

| קובץ | תוכן |
| --- | --- |
| `meetings/scheduler.py` | מנוע השיבוץ. אינו תלוי ב-Django וניתן לשימוש עצמאי |
| `meetings/slots.py` | חלוקת טווחי השעות לחלונות זמן |
| `meetings/importer.py` | קריאה ובדיקה של קובצי ה-Excel |
| `meetings/services.py` | הרצת שיבוץ, נתוני היצע וביקוש, בדיקות התנגשות |
| `meetings/exports.py` | הפקת Excel ו-PDF |
| `meetings/i18n.py` | התרגום לעברית של כל הטקסטים בממשק |
| `meetings/views.py`, `meetings/templates/` | מסכי המארגן |
| `meetings/tests/` | בדיקות אוטומטיות |

## מגבלות הגרסה הראשונה

- רק המבקרים מגישים בקשות; מציגים אינם מדרגים ואינם מסרבים.
- לכל משתתף פגישה אחת בכל חלון זמן (נציג אחד למציג).
- כל המשתתפים זמינים בכל טווחי השעות של התערוכה.
- אין מרווח מעבר נפרד בין פגישות; הוא כלול באורך הפגישה.
- אין ממשק למשתתפים עצמם: המארגן מפיץ את הלוחות.
- הפקת PDF למאות משתתפים אורכת כ-20 שניות.

## פרטיות

המערכת מחזיקה פרטים אישיים של משתתפים (שם, חברה, דוא"ל, טלפון). מי שמפעיל אותה אחראי לעמידה בחוק הגנת הפרטיות ובתקנות אבטחת המידע, וב-GDPR כאשר יש משתתפים מהאיחוד האירופי.
